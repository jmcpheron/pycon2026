Vault pin explorer — drag the slider

An interactive slider for vault-door pin counts, plus an animated hero on the vault study's landing page. Companion to the Python parametric study; inspired by Adam Savage's mini vault build.

2026-05-15 · jmcpheron

What changed

The vault door mechanism study just got a front door. Two new things landed on the same branch:

  • An animated hero SVG at the top of docs/vault/README.md — twelve pins extending and retracting in sync with a cam wheel that rotates ±10°. Five-second loop, inline SMIL, no JavaScript. GitHub renders it in the markdown view directly.
  • A live interactive pin-count explorer at docs/vault/pin-explorer.html — drag a slider from 3 to 30, the SVG layout snaps, and a side panel updates the angle step, the divisor list, the opposing-pair count, and the rack-body thickness budget at the canonical 12 mm central pinion.

The explorer is a single hand-written HTML file. Vanilla JS, no dependencies, ~30 lines of geometry helpers ported from src/vault/geometry.py. The shared stylesheet (cream paper, gold accents, Fraunces serif) gets it for free — it links the same docs/assets/styles.css the rest of the project uses.

// src/vault/geometry.py, ported to JS — kept tiny on purpose
function angleStep(n) { return 360 / n; }
function pinAngles(n, start = -90) {
  const step = angleStep(n);
  const out = [];
  for (let i = 0; i < n; i++) out.push(start + i * step);
  return out;
}
function rackBudgetMm(n) {
  return (2 * Math.PI * PINION_RADIUS_MM / n) - CLEARANCE_MM;
}

Slide to 12: 30° step, six clean opposing-pair chords appear through the hub, rack budget reads 5.98 mm. Slide to 13: chords disappear, pin 0 turns red, a dashed phantom marker shows where its missing partner would have sat, rack budget drops to 5.50 mm. Slide to 24: the racks pinch to 2.84 mm — the visual version of the rack-thinning note I wrote up earlier.

Where this came from

The whole vault study started when I was watching Adam Savage's mini vault-door build and got fixated on one detail. Each pin had a section of straight gear teeth cut into it, and the back of that section — the spine, opposite the teeth — was machined surprisingly thin. More material removed than weight savings would justify.

When the parts went together inside the door it clicked. A single central pinion drives all N racks at once. The racks have to share the perimeter of that one pinion. Each rack's tangential thickness is bounded by

t  ≤  (2π · r_pinion / N)  −  clearance

So the spine of every rack gets machined down to whatever slice it gets. Bigger N → thinner slice. Adam wasn't choosing the shape; the pin count was choosing it for him. That observation kept me up an evening and turned into a Python parametric study about the symmetry, gearing, and packaging trade-offs of radial pin mechanisms.

The explorer is the version of that idea you can poke at without cloning a repo.

For the Tested community

I'm sharing this with the Tested Maker Share community. It's a fan-made educational study inspired by Adam's mini-vault build — not affiliated with Tested, not a reproduction of any specific design, just a love-letter to the geometry. If you got here from there: hi. Fork it, riff on it, change the numbers in src/vault/vault.py, run uv run vault build, and every page re-derives with your inputs.
