A 3D-printed conference badge, rendered by Python in GitHub Actions.

88.9 × 50.8 × 1.6 mm. Embossed identifier, recessed pocket, 14-tooth gear that comes off the printer already spinning. The plate above is regenerated on every push — Python templates the OpenSCAD source, OpenSCAD renders the geometry, the workflow commits the PNG and STL back.

§ 01

The pipeline

Python as the parametric layer. OpenSCAD as the deterministic geometry backend. GitHub Actions as the build server. The plate above is the artifact. 

$ uv run badgeforge build  --name "Your Name" --github "yourhandle"
# → models/card.stl  (binary STL, ready to slice)

$ uv run badgeforge render --angle iso --out docs/assets/badge-hero.png
# → 1600 × 900 PNG via OpenSCAD's --camera + --colorscheme

The same two commands run on every push to main via the Build STL workflow — Ubuntu runner, OpenSCAD installed from apt, xvfb for the headless GL context, then uv run badgeforge … drives both. The resulting card.stl and badge-hero.png are committed back to the repo automatically, so what you see at the top of this page always matches the source under models/card.scad.

Forking the repo and changing --name / --github rebuilds your own personalized badge in CI. No local toolchain required.

§ 03 · Earlier · scadia

The controller

Roughly thirty lines of Python. It reasons over both sensor outputs and stops the loop when there is no concrete reason to spend another iteration. The critic, in this design, is a sensor — not a judge. 

# The interesting question is not "do we trust the critic?" — it's
# "is there evidence another iteration would improve the model?"
#
# We continue only when there is a concrete reason to spend another
# iteration. We stop when the critic has nothing actionable left to
# suggest, when quality is acceptable with no blocking issues, when
# we plateau, or when we run out of budget.
def should_continue(iterations: list[Iteration], max_iterations: int) -> bool:
    if len(iterations) >= max_iterations:
        return False

    last     = iterations[-1]
    critique = last.critique

    # Critic explicitly has no concrete change to suggest.
    if critique.suggested_next_action is None:
        return False
    if critique.done:
        return False

    # Acceptable score and no blocking issues — even if the critic is still
    # offering nits, they don't justify spending another full iteration.
    if critique.score >= 8 and not critique.blocking_issues:
        return False

    # Let the first couple of iterations breathe before plateau-checking —
    # early scores are noisy.
    if len(iterations) < 3:
        return True

    prev = iterations[-2].critique

    # Quality is not improving.
    if critique.score <= prev.score:
        return False

    # Stuck: the same blocking issue surfaced two iterations in a row.
    if set(critique.blocking_issues) & set(prev.blocking_issues):
        return False

    return True

§ 04 · Earlier · scadia

Running the loop

$ git clone https://github.com/jmcpheron/pycon2026
$ cd pycon2026 && uv sync
$ cp .env.example .env  # add ANTHROPIC_API_KEY
$ uv run scadia "a hexagonal nut, M10" --iterations 3

Every iteration's .scad, .png, validation report, and critique land in output/run-<timestamp>/. The manifest.json records the loop's stop reason — useful for the demo reveal.

Showcase

The models/ directory holds checked-in OpenSCAD source. On every push, a GitHub Actions workflow compiles each .scad to a binary .stl and commits the file back — printable geometry, straight from the repo, no local install required.
