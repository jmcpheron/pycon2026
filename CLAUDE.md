# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A 3D-printed business card with a 5-gear compound reduction chain (256:1) plus
the Python tooling that *deconstructs* the card's STEP file into per-part
renders, an exploded-view GIF, and a set of generated engineering writeups.
Two parallel ideas live here: the **physical artifact** (`jmcpheron-card.step`
at the repo root) and the **didactic explainers** (`docs/explainers/*.md`).
Both are downstream of two source-of-truth files; everything else in `docs/` is
regenerated by CI.

## The two Python packages

```
src/cardlab/    →  reads jmcpheron-card.step  →  writes docs/assets/card/*
src/explainers/ →  reads src/explainers/card.py  →  writes docs/explainers/*
```

- **`cardlab`** (CLI: `cardlab`). STEP → STL/GLB/PNG/GIF pipeline. Heavy
  toolchain: build123d, cadquery-ocp, trimesh, cascadio, Pillow, **OpenSCAD +
  xvfb** for rendering. Subcommands: `inspect`, `build`, `render`, `explode`,
  `assemble`. `explode` is the workhorse — produces `parts/`, `manifest.toml`,
  `exploded.glb`, and `exploded.gif`. Rendering uses procedurally-generated
  `.scad` shims that `import()` part STLs frame-by-frame, then PIL stitches
  PNGs into a GIF.
- **`explainers`** (CLI: `explainers`). Light toolchain: **drawsvg**
  (SVG diagrams), **matplotlib** (charts), trimesh (only for `decoding.py`'s
  STL geometry analysis). Each `explainers/<topic>.py` module exposes
  `SLUG` and `build(out_dir) -> Path`; `cli.py` runs them in a fixed order.
  Reusable SVG primitives live in `diagrams.py` (`compound_gear`,
  `animated_compound_gear`, `cross_section`, etc.) and `style.py` (palette).

### The single source of truth: `src/explainers/card.py`

Every gear parameter (tooth counts, module, card dimensions, ratios) lives
there. Explainer modules import `from explainers import card` and reference
`card.BIG_TEETH`, `card.RATIO_PER_STAGE`, etc. **Never hardcode these
numbers** — the test `test_no_drift_between_sections` enforces that every
rendered explainer markdown contains the textual value of `card.BIG_TEETH`,
`card.PINION_TEETH`, and `card.MODULE_MM`, and will fail loudly if a stray
literal sneaks in.

## Common commands

Install: this repo uses **uv**. There are three optional-dependency groups
because the toolchains have very different weights:

```bash
uv sync --extra dev               # pytest only — for CI smoke tests
uv sync --extra explainers        # + drawsvg, matplotlib, trimesh (fast)
uv sync --extra step              # + build123d, cadquery-ocp, cascadio (heavy)
uv sync --all-extras              # everything; CI uses this
```

Build / rebuild generated assets:

```bash
# Regenerate one explainer page + its SVGs (fast):
uv run --extra explainers explainers build ratios

# Regenerate all explainer pages + index:
uv run --extra explainers explainers build

# Decompose the STEP into parts/manifest/exploded GIF (needs OpenSCAD + xvfb):
xvfb-run -a uv run --extra step cardlab explode \
    --in jmcpheron-card.step --out docs/assets/card/ \
    --strategy card-layered --frames 24

# Quick metadata-only look at the STEP:
uv run --extra step cardlab inspect jmcpheron-card.step
```

Tests:

```bash
xvfb-run -a uv run pytest                                   # full suite (CI form)
uv run --extra dev --extra explainers pytest tests/test_explainers.py   # explainers only
uv run --extra dev --extra explainers pytest tests/test_explainers.py::test_card_constants_consistent -v
```

The test modules call `pytest.importorskip(...)` for their heavy deps, so
running pytest without the matching extra silently skips that module rather
than failing.

## Generated content and the auto-commit CI loop

Anything under `docs/assets/card/`, `docs/explainers/`, or `step-demo/`
(except hand-edited `*.toml` manifests) is regenerated and **auto-committed
back to main** by one of three workflows:

| Workflow                     | Trigger paths                       | Writes to                    |
|------------------------------|-------------------------------------|------------------------------|
| `build-card.yml`             | `jmcpheron-card.step`, `src/cardlab/**` | `docs/assets/card/**`    |
| `build-explainers.yml`       | `src/explainers/**`                 | `docs/explainers/**`         |
| `build-step.yml`             | `step-demo/**`, `src/cardlab/**`    | `step-demo/**`               |

These workflows race each other (and human pushes) on `main`. They each write
to **disjoint paths** and use a rebase-and-retry loop on push rejection — so
conflicts are always resolvable. When editing source files that drive a
workflow, expect a follow-up auto-commit a few minutes after your push.

`ci.yml` is the read-only test gate. `pages.yml` deploys `docs/` to GitHub
Pages. Python **3.13 is excluded** from the matrix (`cadquery-ocp==7.8.1.1.post1`
pulls vtk==9.3.1, which has no cp313 wheels).

## Conventions worth knowing

- **Matplotlib SVG determinism**: `mpl.rcParams["svg.hashsalt"] = "explainers"`
  is set in modules that emit matplotlib SVGs. Without it the auto-commit
  workflow churns on every run because matplotlib randomises element IDs.
- **`compound_gear()` and `animated_compound_gear()`** in
  `src/explainers/diagrams.py` are the canonical gear primitives. Both
  delegate to `_gear_shapes()`. The animated variant wraps shapes in a
  `dw.Group` with a SMIL `<animateTransform>`; GitHub renders animated SVG
  in READMEs via its camo proxy, so this is the established way to add
  motion to a hero diagram (see `gear-ratios-animated.svg`).
- **Pinned vs permissive deps in `[project.optional-dependencies] step`**:
  `cadquery-ocp` is pinned *exactly* because OCCT's STL writer's float
  formatting drifts across versions and would churn auto-committed STLs;
  `cascadio` is permissive because PyPI prunes old versions. Read the
  comments in `pyproject.toml` before bumping anything in `step`.
- **Order matters for `EXPLAINERS`** in `src/explainers/cli.py` — it's the
  order the generated `docs/explainers/index.md` lists sections.
- **Two licenses**: code is MIT (`LICENSE`); 3D files are CC BY-SA 4.0
  (`LICENSE-3D-FILES`). The `jmcpheron-card.step` source is the latter.
